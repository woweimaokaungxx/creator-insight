# 24 · 平台适配器

> 统一接口见 `app/adapters/base.py`（`docs/13` 边界：Adapter 只负责「获取」，不触碰 AI / DB / 验证 / Obsidian）。
> 本文记录抖音与 B 站的**实际获取逻辑、Cookie 策略与风控应对**。
>
> 最后更新：2026-09-14（V0.14 补齐 B 站 UP 主目录抓取与登录态）

## 一、统一接口

| 方法 | 基类 | 作用 |
|------|------|------|
| `parse_input(raw)` | ✅ 抽象 | 分享文案 / 短链 / 长链 → `ParsedURL(platform, content_id)` |
| `fetch_creator(platform_id)` | ✅ 抽象 | 博主基本信息（名称、主页 URL） |
| `fetch_content_meta(parsed)` | ✅ 抽象 | 单条视频元数据（含点赞/评论/转发/收藏） |
| `fetch_transcript(content)` | ✅ 抽象 | 平台字幕；拿不到返回 `None` → 由调用方决定是否走 Whisper |
| `download_media(content, dir)` | ➖ 可选 | 下载音频（Whisper 兜底与「回听」用） |
| `fetch_creator_videos(id, cursor, max_items)` | ➖ 可选 | 博主作品目录（**批量模式**与**自动监控**用） |
| `resolve_creator(raw)` | ➖ 非基类 | 主页/作品链接 → 博主 ID + 昵称；各 adapter 自行实现，调用前需确认存在 |

> **注意**：`resolve_creator` **不在基类**中。`mode=all` 与自动监控会调用它，缺失的 platform 会直接 `AttributeError`。V0.14 已为 B 站补齐。

## 二、抖音（`app/adapters/douyin.py`）

### 2.1 Cookie 四级策略

抖音对匿名请求风控严格，按优先级依次尝试：

1. `config.json` 的 `monitor.douyin_cookie`（账号页手动写入）
2. `data/cookies/douyin_login.txt`（扫码登录后导出的登录态）
3. `data/cookies/douyin_{vid}.txt`（上次自动生成的匿名缓存）
4. Playwright 驱动系统 Chrome/Edge **现场生成**匿名 Cookie

### 2.2 单视频与博主目录

- 元数据：详情 API；风控时用页面 `og:title` / `data-e2e` 兜底
- 目录：`_fetch_videos` 分页调目录 API；被 a_bogus 风控返回空时，回退 **Playwright 登录态 profile**（`monitor.profile_path`）拦截目录 API 抓取
- 下载：yt-dlp + 三级 cookie 策略

## 三、B 站（`app/adapters/bilibili.py`）

### 3.1 Cookie 策略（V0.14）

| 来源 | 说明 |
|------|------|
| `platforms.bilibili.cookie` | 用户配置（`k1=v1; k2=v2`，至少含 `SESSDATA`） |
| **匿名设备指纹（自动）** | 无 `buvid3` 时自动调 `x/frontend/finger/spi` 获取 `buvid3`/`buvid4` 并缓存 1 小时 |

> **关键发现（实测）**：带上匿名指纹后，**UP 主投稿目录接口无需登录 Cookie 也能正常返回**（此前匿名请求会被 WAF 直接 `412`）。因此 Cookie 主要用于**字幕**。

请求头统一带 `User-Agent` / `Referer` / `Origin`（降低 WAF 拦截概率）。

### 3.2 单视频元数据

1. **主路径**：`x/web-interface/view?bvid=`（或 `aid=av号`）→ title / owner / pubdate / duration / **stat**
2. **互动映射**：`stat.like→点赞`、`reply→评论`、`share→转发`、`favorite→收藏`
3. **兜底**：API 返回空（412）→ yt-dlp `extract_info(download=False)`，**但互动数据会缺失**

### 3.3 字幕（重要限制）

```
_resolve_cid（再调一次 view API 取 pages[0].cid，多 P 只取第 1 P）
  → x/player/v2?bvid=&cid=  → data.subtitle.subtitles[]
  → 取第一条字幕轨 → 下载 subtitle_url（JSON）→ body[] 拼 text_full + segments
```

- **需要登录 Cookie**：未登录时 `player/v2` 通常不返回 `subtitles` → 返回 `None`
- 结果是**实际大量 B 站视频会回退到 Whisper 本地转写**（慢但可用）
- 任何异常一律静默返回 `None`（不阻断流程）

### 3.4 UP 主投稿目录（V0.14 新增）

接口：`x/space/wbi/arc/search?mid=&ps=&pn=&order=pubdate`

**必需 wbi 签名**：

```
nav 接口 → wbi_img.img_url / sub_url → 取文件名（不含扩展名）作 img_key / sub_key
mixin_key = (img_key + sub_key) 按固定置换表重排后取前 32 位
参数 + wts → 过滤 !'()* → 按 key 升序 → urlencode → 拼 mixin_key → md5 = w_rid
```

密钥与指纹均**缓存 1 小时**，避免每页重复取。

**分页规则**：

| 项 | 规则 |
|----|------|
| 每页条数 | `monitor.per_page`，钳制 1~50（B 站上限 50） |
| 最大页数 | `monitor.max_pages`（默认 20） |
| 终止条件 | 返回条数 < 每页条数，或接口报错，或达到 `max_items` |
| 翻页限速 | 每页之间 `sleep(0.5)` |

**互动数据说明**：

- 空间接口 `vlist` **只提供评论数**（`comment`）与播放数（进 `raw_meta`）
- 点赞/转发/收藏需逐条调 `view` API → 由 `platforms.bilibili.fetch_video_stats=true` 控制（默认 false，开启后带 `0.3s` 逐条限速）

### 3.5 `resolve_creator`

| 输入 | 处理 |
|------|------|
| `space.bilibili.com/{mid}` | 直接提取 mid → `acc/info`（wbi 签名）取昵称 |
| 视频链接 / BV 号 / av 号 | `view` API 反查 `owner.mid` + `owner.name` |
| 其它 | 抛 `ValueError` |

| 能力 | 抖音 | B 站 |

## 五、风控与排错

| 现象 | 平台 | 原因与处理 |
|------|------|-----------|
| `412` | B 站 | WAF 拦截。已自动补 `buvid` + `Origin`；仍失败则在系统设置填 `platforms.bilibili.cookie` |
| `-352` | B 站 | 业务风控。通常是空间接口；配置 Cookie 后重试 |
| 字幕始终为空 | B 站 | 未登录（字幕接口需 Cookie）；回退 Whisper 属预期行为 |
| 目录返回空 | 抖音 | a_bogus 风控 → 配置 `monitor.profile_path` 走 Playwright 登录态 |
| 目录检测到多作者 | 两者 | 触发目录审核失败（`_audit_catalog`），保留原始数据待复核 |

**日志线索**：两个 adapter 在风控/失败时都会打印带平台前缀的提示（`[bilibili]` / `[douyin]`）。
