# 21 · 系统设置（配置中心）

## 1. 目标

把「手工编辑 `config/config.json`」升级为**可视化配置中心**：AI 模型与密钥、搜索、通知、Obsidian、抓取监控、验证参数等全部可在页面修改，**保存即生效**（无需重启），并支持一键测试 AI 连通性。

## 2. 能力清单

| 能力 | 说明 |
|------|------|
| 读取配置 | 返回全部可配置段；**密钥类字段脱敏**（只返回掩码） |
| 修改配置 | 局部提交（只写改动的段与字段）；密钥留空/掩码 → **保留原值**，`null` → 清空 |
| 保存即生效 | 写入后**热重载**受影响的运行时单例（AI 网关 / Obsidian 适配器） |
| 测试 AI 连接 | 发一次最小真实请求，验证 `base_url` / `api_key` / `model` 可用 |
| 用量上限与告警 | 每日 AI 调用上限（超限拒绝）+ 用量告警通知（成本控制） |
| 运行时状态 | 云端/本地 AI 是否就绪、Obsidian 是否启用、今日用量 |

## 3. 页面结构

入口：左侧导航 **系统 → 系统设置**（`/settings`）。

**顶部「运行状态」卡片**：四个状态徽标（云端 AI / 本地兜底 / Obsidian / 今日调用）+ 「测试 AI 连接」+「保存全部」。

**下方按配置段分组的表单卡片**：

| 分组 | 主要字段 |
|------|---------|
| AI 云端 | `base_url` / `model` / `api_key` / `max_tokens` / 每日调用上限 / 告警阈值 |
| AI 本地兜底 | `enabled` / `base_url` / `model` |
| 任务模型路由 | 6 个任务分别指定 `cloud` 或 `local` |
| 搜索（证据收集） | `provider` / `tavily_api_key` / `fallback` / `max_results` |
| 通知 | `enabled` / `channels`（多选）/ `webhook_url` / `smtp.*` |
| Obsidian | `vault_path` / `root_folder` / `write_enabled` / `sync_*` |
| 抓取监控 | `enabled` / `max_pages` / `per_page`（抖音登录态在「自动监控」页） |
| 验证与统计 | `auto_apply` / 置信度门槛 / 撤销窗口 / 样本量门槛 / 调度开关与间隔 |
| 应用 | `host` / `port` / `data_dir`（**需重启**）/ `log_level` |

## 4. 接口契约

```
GET   /api/settings            # 全部配置（密钥脱敏）+ 运行时状态
PATCH /api/settings            # 局部写入（{section: {field: value}}），写入后热重载
POST  /api/settings/ai/test    # 发一次最小真实请求验证 AI 配置
```

**GET 响应：**

```json
{
  "config": {
    "ai": { "cloud": { "api_key": "sk-c****vy1i", "base_url": "...", "model": "..." },
            "daily_call_limit": 0, "daily_call_warn": 0, "task_model_map": { "...": "cloud" } },
    "notify": { "channels": ["local"], "smtp": { "password": "" } }
  },
  "secrets_configured": { "ai.cloud.api_key": true, "search.tavily_api_key": false },
  "mask": "****",
  "restart_required_fields": ["app.host", "app.port", "app.data_dir"],
  "runtime": {
    "ai_cloud": true, "ai_local": true, "obsidian_active": false,
    "ai_usage_today": 0, "ai_usage_date": "2026-09-12"
  }
}
```

**错误语义**：不可写入的配置段 / 非法请求体 → `409`；AI 测试失败 → `409`（配置类原因）或 `502`。

## 5. 脱敏规则（硬性）

需脱敏字段（只返回掩码，写入时留空/掩码则不修改）：

| 配置路径 |
|----------|
| `ai.cloud.api_key` |
| `search.tavily_api_key` |
| `notify.webhook_url` |
| `notify.smtp.password` |
| `monitor.douyin_cookie` |

写入语义：**空串或含掩码 → 保留原值**；**`null` → 显式清空**；其它值 → 覆盖。页面与日志均不出现明文密钥。

## 6. 保存即生效：单例热重载（关键技术点）

多数模块每次调用实时读配置，但以下两个在**导入时**就把配置缓存进了对象：

| 模块 | 缓存方式 | 处理 |
|------|---------|------|
| `app/ai/provider.py` | `ai_gateway = AIGateway()` 在导入时构造 provider | 新增 `AIGateway.reload()`：清空 `_cache` 后 `_init_providers()` |
| `app/services/obsidian.py` | `ObsidianAdapter.__init__` 缓存 `root/folder/enabled` | 新增 `ObsidianAdapter.reload()` |

**关键陷阱**：其它模块用 `from ..ai.provider import ai_gateway` 在**导入时绑定对象引用**；若重新赋值模块级变量（`ai_gateway = AIGateway()`），旧引用仍指向原对象，配置**不会生效**。

**正确做法**：调用实例的 `reload()` **原地更新内部状态**，引用不变，所有模块自动生效。

## 7. 配置边界说明（对齐 docs/13）

`docs/13-module-boundaries.md` 要求「所有模块只能通过 SQLite 交换数据」。

该约束针对**模块间业务数据交换**（业务链路全程 SQLite）；本功能读写的 `config/config.json` 是**单一配置源**（与 `data/account_status.json`、`data/ai_usage.json` 同属配置/运行状态），**不参与业务数据交换**，因此不违反该约束。

## 8. AI 用量上限与告警（对齐 docs/14 风险 #14）

`docs/14-risk-register.md` P1 要求「AI 调用加每日上限与告警」，实现如下：

| 配置 | 默认 | 行为 |
|------|------|------|
| `ai.daily_call_limit` | `0`（不限） | 当日调用达到上限 → **拒绝调用**并返回明确错误 |
| `ai.daily_call_warn` | `0`（不告警） | 当日调用首次达到阈值 → 推送一条「AI 用量告警」通知 |

- 计数落盘 `data/ai_usage.json`（**跨日自动归零**，重启后仍准确）
- 校验挂在 `AIGateway.chat()` 统一入口，不散落到各业务模块
- 告警通过现有 `notify` 服务推送（沿用已配置的通道）

## 9. 需重启才生效的字段

`app.host` / `app.port` / `app.data_dir` 改动必须**重启服务**才生效，界面已标注「重启后生效」。

## 10. 常见问题

| 现象 | 原因与处理 |
|------|-----------|
| 保存后密钥好像没变 | 属预期：留空或提交掩码值即「不修改」。要更换请填新密钥；要清空请用清空操作 |
| 改了 AI 模型但调用仍是旧的 | 保存会自动热重载；若仍异常，检查是否直接改了 `config.json` 而未通过页面保存 |
| 提示「已达每日 AI 调用上限」 | 调大 `ai.daily_call_limit` 或设为 `0`，次日自动恢复 |
| 提示「未配置云端 AI」 | `ai.cloud.api_key` 为空，填写后保存 |
| Obsidian 一直未启用 | 需同时满足 `vault_path` 指向存在的目录且 `write_enabled` 为真 |
