# 配置过程与本地 AI 转写

本文档说明 creator-insight 的**配置流程**和**本地 Whisper 转写功能**，参考了 douyin-creator-distill 的配置与本地转写运行环境设计。

## 一、配置过程

### 1.1 首次安装

```powershell
# 创建虚拟环境并安装依赖（首次）
start.bat

# 或手动：
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

### 1.2 创建配置文件

`start.bat` 首次运行会自动从 `config.example.json` 复制出 `config.json`。若需手动：

```powershell
Copy-Item config\config.example.json config\config.json
```

配置文件只保存在本机（已加入 .gitignore）：

| 配置段 | 用途 |
|--------|------|
| `app` | 服务 host/port、数据目录 |
| `ai.cloud` | 云端分析模型（DeepSeek 等 OpenAI 兼容接口） |
| `ai.local_fallback` | 本地 Ollama 兜底（可选） |
| `transcription.whisper` | **本地转写配置**（见下） |
| `search` | Tavily 证据搜索 |
| `verification` | 硬预测自动过 / 撤销窗口 / 调度 |
| `monitor` | 抖音 cookie、**登录态 profile**（批量抓取）、关注监控 |
| `notify` | 站内 / Webhook / 邮件通知 |

### 1.3 运行环境诊断

参考 douyin-creator-distill 的 `npm run doctor`，提供一键诊断：

```powershell
.venv\Scripts\python scripts\doctor.py
```

检查项：
1. `config/config.json` 完整性
2. AI 云端 key 是否已配置
3. **FFmpeg**（本地转写预处理）
4. **faster-whisper** 是否安装 + 模型就绪
5. **playwright** + 系统 Chrome/Edge（抖音自动 cookie）
6. **yt-dlp**（视频下载）
7. 数据目录可写
8. 后端可启动

输出 `✅ N 正常 | ⚠️ M 警告 | ❌ K 缺失`。警告项为可选能力，缺失项需修复。

## 二、本地 AI 转写功能

### 2.1 配置（`config.json` → `transcription`）

```json
"transcription": {
  "prefer": "platform_subtitle",
  "defaultProvider": "whisper",
  "whisper": {
    "model": "small",       // 模型档位：tiny/base/small/medium/large-v3
    "device": "cpu",        // cpu / auto / cuda
    "compute_type": "int8", // int8（CPU 推荐）/ float16
    "language": "",         // 留空自动检测；可设 zh/en
    "retain_media": false   // true 保留中间音频，false 转写后删除
  },
  "artifacts_dir": "./data/transcripts/whisper"
}
```

### 2.2 转写链路（参考 douyin-creator-distill）

**FFmpeg 已接入主流程**：`whisper_transcribe` 内部先 `extract_audio`（FFmpeg 提取 16kHz 单声道 wav），再喂 faster-whisper。手动 ingest（`/api/ingest`）和监控自动处理（`creator_monitor`）都走这一链路。

```
媒体文件 (mp4/webm/m4a)
  -> FFmpeg 提取 16kHz 单声道 wav（准确率↑ 计算↓，`-vn -ac 1 -ar 16000`）
  -> faster-whisper 转写（VAD 过滤静音）
  -> 落盘产物到 data/transcripts/whisper/：
       {key}.md    正文
       {key}.json  逐段（含 text_full，供断点续转）
       {key}.srt   时间轴字幕
  -> 默认删除中间 _16k.wav（retain_media=false）
  -> 返回 {text_full, segments, language, files}
```

**实测**：21MB 视频转写 104s（含音频提取），产物 md/json/srt 齐全，中间 wav 自动清理。

**耗时参考（实测）**：

| 音频 | CPU `small`+`int8` | GPU `small`+`float16`（RTX 2060） |
|------|-------------------|-----------------------------------|
| 10 秒 | 5.8s（1.7x 实时） | **1.4s（7.1x 实时）** |
| 84 分钟 | 约 3 小时（0.4x 实时，实测） | **约 12 分钟**（按 7x 推算） |

> 模型加载约 50s（首次；同进程内会复用）。转写期间任务卡显示 `Whisper 转写 12.5/84.5 分钟（约剩 X 分钟）`。

### 2.2.1 启用 GPU 加速（实测约 4 倍）

**前置**：NVIDIA 显卡 + 驱动（`nvidia-smi` 能正常输出）。

改 `config.json` 的 `transcription.whisper`：

    "device": "cuda",
    "compute_type": "float16",

> **最简方式（推荐）**：打开前端「系统设置」→「本地转写（Whisper）」分组，顶部有 **「启用 GPU 加速」开关** —— 一键切换 `device` / `compute_type` / `batch_size` 三个字段，点「保存全部」生效。

**若未装系统级 CUDA Toolkit**（多数情况），用 pip 装运行时库即可 —— 不需要下载数 GB 的 Toolkit：

```powershell
.venv\Scripts\pip install nvidia-cublas-cu12 nvidia-cudnn-cu12 nvidia-cuda-runtime-cu12
```

程序在 `device=cuda` / `auto` 时会**自动**把 `site-packages/nvidia/*/bin` 注入 DLL 搜索路径（`setup_cuda_dlls()`，同时写 `add_dll_directory` 与 `PATH`），**无需手工配置环境变量**。

**常见报错与处理**：

| 报错 | 原因 | 处理 |
|------|------|------|
| `Library cublas64_12.dll is not found or cannot be loaded` | 缺 cuBLAS / cuDNN / CUDA Runtime | 装上面三个 pip 包 |
| `Library cudnn64_9.dll is not found` | 缺 cuDNN | 装 `nvidia-cudnn-cu12` |
| `out of memory` | 显存不足 | 换更小模型或回到 CPU（显存参考：`small`≈1GB / `medium`≈2GB / `large-v3`≈4GB+） |

### 2.2.2 批量推理：把 GPU 打满（实测再快 4.5 倍）

默认走 `WhisperModel.transcribe()` 是**逐段串行解码**（`condition_on_previous_text=True` 使每段依赖前一段输出），GPU 大部分时间在等 CPU，利用率只有约 **30%**。

改用 faster-whisper 的 **`BatchedInferencePipeline`**（批处理替代串行）：

    "batch_size": 16,

**实测**（RTX 2060 / `small` / `float16` / 600 秒音频）：

| 方案 | 纯转写 | 速度 | GPU 峰值 |
|------|-------|------|---------|
| 逐段串行（`batch_size: 0`） | 68.4s | 8.8x | 54% |
| **批量推理 `batch_size: 16`（默认）** | **15.2s** | **39.5x** | **99%** |
| 批量 + `beam_size=1` + `batch_size: 24` | 7.0s | 85.1x | 97% |

> **取舍**：批量模式下 VAD 分段更粗（片段 263 → 23，约每段 26 秒），**SRT 时间戳粒度随之变粗**，但文本完整性不受影响。若需要逐句级时间轴（回听定位），把 `batch_size` 设为 `0` 回退逐段模式。

**其它加速手段**：

- 换更小模型（`base` 约快 2~3 倍，`tiny` 更快但准确率下降）
- 为平台配置登录 Cookie（B 站字幕需登录；有 CC 字幕就不必本地转写）

> 转写有**断点续转**：同一媒体（路径+大小+修改时间）已转写完成时直接读缓存，不会重复计算。

### 2.3 增强特性

| 特性 | 说明 |
|------|------|
| **FFmpeg 预处理** | 先提 16kHz 单声道 wav，转写更准、更快（失败自动回退原文件） |
| **产物落盘** | 正文/逐段/字幕三种产物，可追溯、可复用（如 SRT 做剪辑） |
| **断点续转** | 同一媒体（路径+大小+时间）已转写则读缓存 json 直接返回，秒级 |
| **语言自动检测** | 留空时自动识别，避免英文内容强转中文空转写 |
| **VAD 过滤** | 自动跳过静音段，节省计算 |

### 2.4 依赖

- **faster-whisper**：`pip install faster-whisper`（需 CPU/GPU）
- **FFmpeg**：系统安装（转写预处理）；缺失时回退直接处理原文件

本地转写效果参考：`data/transcripts/whisper/` 下的真实产物（如影视飓风火箭视频）。

## 二.5、批量抓取博主目录（登录态 Chrome）

抖音主页目录 API 需要 `a_bogus` 签名 + 登录态，纯 httpx 必被风控。批量抓取用**登录态 Chrome profile**（参考 douyin-creator-distill）。

### 配置

```json
"monitor": {
  "profile_path": "C:/Users/xxx/AppData/Local/Google/Chrome/User Data/DouyinScraper"
}
```

### 原理

```
fetch_creator_videos
  ├─ httpx 目录 API（匿名）→ 被 a_bogus 拦截返回空
  └─ 回退 Playwright 登录态 profile：
       launch_persistent_context(profile_path, channel=chrome)
       → 访问博主主页，滚动加载
       → 拦截目录 API（aweme/post）响应，拿到完整 aweme_list（含互动数据）
       → 每条转 ContentInfo（赞/评/转/藏）
```

### 准备登录态 profile

1. 复制一个 Chrome 快捷方式，加 `--user-data-dir="...\User Data\DouyinScraper"`
2. 用它打开并**登录抖音**（微信/手机号扫码均可）
3. 关闭 Chrome，把该路径填进 `monitor.profile_path`

### 实测

- 影视飓风主页 → 抓取 **39 个作品**，每条含点赞/评论/转发/收藏（如"可回收火箭"赞 129万/评 28109/转 11.2万）
- JSON 审核通过（去重/必填/作者归属/互动完整度）

## 三、本地 Ollama LLM 兜底

当云端模型不可用或希望完全本地运行时，可用 **Ollama 提供本地 LLM 兜底**。

### 3.1 安装 Ollama 与拉取模型

```powershell
# 安装 Ollama（Windows）
winget install --id Ollama.Ollama --accept-package-agreements

# 拉取本地模型（CPU 推荐 qwen2.5:0.5b ~400MB 或 3b ~2GB）
ollama pull qwen2.5:0.5b

# 确认模型已就绪
ollama list
```

> 若从官方源下载慢，可设置国内镜像或代理后再 `ollama pull`。

### 3.2 配置（`config.json` → `ai.local_fallback`）

```json
"ai": {
  "local_fallback": {
    "enabled": true,                              // 启用本地兜底
    "provider": "ollama",
    "base_url": "http://127.0.0.1:11434",        // Ollama 服务地址
    "model": "qwen2.5:0.5b"                       // 本地模型名
  }
}
```

### 3.3 兜底机制

`AIGateway` 按 `task_model_map` 路由，默认**云端优先**，云端失败时自动降级到本地 Ollama：

```
route=cloud → 先 cloud，失败 → 本地 Ollama 兜底
route=local → 先本地 Ollama，失败 → 云端
```

所有任务（总结/Claim/预测/验证/简体化）都走这套路由。

### 3.4 诊断

`doctor.py` 会检测 Ollama 服务、已装模型和配置的本地模型是否就绪：

```
[4b] 本地 LLM 兜底（Ollama）
  ✅ Ollama 服务可用 http://127.0.0.1:11434  已装模型: qwen2.5:0.5b
  ✅ 配置的本地模型就绪 qwen2.5:0.5b
```

## 四、云端 / 本地通道

当前 `defaultProvider: "whisper"`（转写本地优先）。后续可按 douyin-creator-distill 扩展 `cloud-first` 优先级续接：

```
cloud-first（云端每日限额）→ 额度耗尽 → 本地 Whisper 续接
whisper-first（本地优先）→ 本地失败 → 云端续接
```

每条作品的实际转写通道会记录到 transcript 表（`source` 字段：`whisper_local` / `cloud_asr` / `platform_subtitle`）。
